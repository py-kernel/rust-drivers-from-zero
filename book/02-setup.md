# Глава 2. Подготовка

В этой главе мы установим Rust, запустим тесты готового драйвера и разберём файл `Cargo.toml`. Всё выполняется на обычном компьютере.

## Установка Rust

Официальный способ - утилита `rustup`. Инструкция для вашей системы находится на сайте [rustup.rs](https://rustup.rs). После установки откройте новый терминал и проверьте результат.

```sh
rustc --version
cargo --version
```

Обе команды должны вывести номер версии. Код руководства проверялся на `rustc` 1.75.0. В `Cargo.toml` указано `rust-version = "1.75"`, и более старые компиляторы cargo откажется использовать.

Утилита `cargo` - сборщик и менеджер пакетов. Она скачивает зависимости, компилирует код и запускает тесты.

## Запуск тестов

Склонируйте репозиторий и перейдите в каталог драйвера.

```sh
cd examples/lm75
cargo test
```

При первом запуске cargo скачает зависимости, и это займёт некоторое время. В конце вывода должна появиться строка о том, что 11 тестов пройдены.

```
running 11 tests
test address_from_pins ... ok
test bus_error_is_passed_up ... ok
...
test result: ok. 11 passed; 0 failed
```

Плата при этом не подключена. Как тесты обходятся без неё, объясняет [глава 6](06-testing.md).

## Файл Cargo.toml

```toml
[package]
name = "lm75-guide"
version = "0.1.0"
edition = "2021"
description = "Учебный драйвер датчика температуры LM75 на embedded-hal 1.0"
license = "MIT OR Apache-2.0"
rust-version = "1.75"

[dependencies]
embedded-hal = "1.0.0"

[dev-dependencies]
embedded-hal-mock = { version = "0.11.1", default-features = false, features = ["eh1"] }
```

Раздел `[package]` описывает сам крейт. Поле `edition` задаёт редакцию языка, а `rust-version` - минимальный компилятор.

Раздел `[dependencies]` перечисляет то, что нужно драйверу для работы. Здесь только `embedded-hal`, то есть трейты. Это сознательное решение. Чем меньше зависимостей у драйвера, тем легче его использовать в чужом проекте.

Раздел `[dev-dependencies]` перечисляет то, что нужно только тестам. Крейт `embedded-hal-mock` подменяет настоящую шину. В пользовательский проект он не попадает. Опция `features = ["eh1"]` включает поддержку `embedded-hal` 1.0, а `default-features = false` отключает остальное.

Запись `"1.0.0"` без дополнительных знаков означает "совместимо с 1.0.0", то есть подойдёт любая версия 1.x, не ниже 1.0.0.

## Проверка под микроконтроллер

Драйвер объявлен как `#![no_std]`. Это значит, что он не использует стандартную библиотеку, которой на микроконтроллере нет. Компилятор сам откажется собирать код, в котором случайно появится `Vec` или `println!`.

Чтобы убедиться, что драйвер собирается и под настоящую цель, добавьте target для Cortex-M0+ (на нём работает RP2040 из Raspberry Pi Pico) и соберите крейт.

```sh
rustup target add thumbv6m-none-eabi
cargo build --target thumbv6m-none-eabi
```

Эта проверка включена в CI-конфигурацию репозитория (`.github/workflows/ci.yml`).

## Структура проекта

```
examples/lm75/
  Cargo.toml        описание крейта
  src/lib.rs        код драйвера
  tests/driver.rs   тесты
```

Тесты лежат в каталоге `tests/`, а не внутри `src/`. Каждый файл там компилируется как отдельная программа, которая видит только публичный интерфейс крейта. Так тест проверяет драйвер глазами пользователя. Кроме того, такие тесты собираются со стандартной библиотекой, и в них доступны `vec!` и другие удобства, закрытые в `no_std`.
