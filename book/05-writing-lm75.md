# Глава 5. Пишем драйвер LM75

Полный код находится в `examples/lm75/src/lib.rs`. Разберём его по частям в том порядке, в котором он написан.

## Заголовок крейта

```rust
#![no_std]
#![deny(missing_docs)]

use embedded_hal::i2c::I2c;
```

Первая строка отключает стандартную библиотеку ([глава 4](04-rust-minimum.md)). Вторая превращает отсутствие документации у публичных элементов в ошибку компиляции. Для библиотеки это полезное ограничение: интерфейс, который нельзя описать, обычно плохо продуман.

Третья строка подключает трейт `I2c`. Его путь в `embedded-hal` 1.0 - `embedded_hal::i2c::I2c`.

## Константы вместо магических чисел

```rust
mod register {
    pub const TEMPERATURE: u8 = 0x00;
    pub const CONFIGURATION: u8 = 0x01;
}

const SHUTDOWN_BIT: u8 = 0b0000_0001;
const DEGREES_PER_STEP: f32 = 0.125;
```

Значения взяты из таблиц [главы 3](03-i2c-and-datasheet.md). Запись `register::TEMPERATURE` читается лучше, чем голое `0x00`, и при ошибке в номере регистра её достаточно исправить в одном месте. Модуль `register` не помечен как `pub`, поэтому снаружи крейта он не виден.

Двоичная запись `0b0000_0001` с подчёркиваниями позволяет увидеть, какой именно бит выбран.

## Адрес

```rust
pub struct Address(u8);

impl Address {
    pub const fn from_pins(a2: bool, a1: bool, a0: bool) -> Self {
        Address(0b100_1000 | ((a2 as u8) << 2) | ((a1 as u8) << 1) | (a0 as u8))
    }

    pub const fn bits(self) -> u8 {
        self.0
    }
}
```

Можно было принимать адрес просто числом `u8`. Тогда пользователь мог бы передать `0x90` или `0x20`, и ошибка проявилась бы только на плате. Отдельный тип `Address` с единственным конструктором `from_pins` исключает такие значения. Невозможное состояние нельзя создать, поэтому его не нужно проверять.

Разберём выражение. Четыре старших бита адреса фиксированы: `100_1000` равно `0x48`. Затем для каждого вывода значение `bool` превращается в 0 или 1 (`a2 as u8`), сдвигается на нужную позицию и добавляется операцией ИЛИ.

Для `from_pins(true, false, true)` получится `0b100_1000 | 0b100 | 0b000 | 0b001`, то есть `0b100_1101`, или `0x4D`.

Слово `const` перед `fn` разрешает вызывать функцию на этапе компиляции. Оно не обязательно, но ничего не стоит.

Адрес по умолчанию задан отдельно.

```rust
impl Default for Address {
    fn default() -> Self {
        Self::from_pins(false, false, false)
    }
}
```

## Тип ошибки

```rust
#[derive(Debug)]
pub enum Error<E> {
    I2c(E),
}
```

В драйвере пока один вид ошибки, и казалось бы, обёртка лишняя. Но `Error<E>` оставляет место для будущего. Когда у датчика появятся другие ошибки (например, "неверный идентификатор чипа"), их можно будет добавить новыми вариантами. Код, который уже использует `Error::I2c`, продолжит работать.

Параметр `E` - тип ошибки конкретной шины. Драйвер не знает его заранее и пропускает как есть.

Атрибут `#[derive(Debug)]` автоматически создаёт реализацию, которая позволяет печатать ошибку при отладке.

## Структура драйвера

```rust
pub struct Lm75<I2C> {
    i2c: I2C,
    address: Address,
}

impl<I2C: I2c> Lm75<I2C> {
    pub fn new(i2c: I2C, address: Address) -> Self {
        Lm75 { i2c, address }
    }

    pub fn destroy(self) -> I2C {
        self.i2c
    }
}
```

Конструктор не обращается к шине. Это правило хорошего тона для драйверов: создание объекта не должно давать побочных эффектов и не должно завершаться ошибкой. Все обращения к железу происходят в методах.

Метод `destroy` принимает `self` по значению. Драйвер при этом поглощается, а шина возвращается вызывающему. Это нужно, чтобы передать шину другому коду. В тестах он нужен по ещё одной причине, о которой пойдёт речь в [главе 6](06-testing.md).

## Чтение температуры

```rust
pub fn read_temperature_raw(&mut self) -> Result<i16, Error<I2C::Error>> {
    let mut buffer = [0u8; 2];
    self.i2c
        .write_read(self.address.bits(), &[register::TEMPERATURE], &mut buffer)
        .map_err(Error::I2c)?;
    Ok(i16::from_be_bytes(buffer) >> 5)
}
```

Построчно.

1. Создаётся буфер на два байта.
2. Вызывается `write_read`. Первый аргумент - адрес. Второй - то, что нужно записать, то есть номер регистра температуры. Третий - буфер, в который шина положит ответ.
3. Ошибка шины оборачивается в `Error::I2c`, и оператор `?` возвращает её вызывающему.
4. Два байта собираются в `i16` (старший первым), и значение сдвигается вправо на пять бит. Сдвиг отбрасывает неопределённые младшие биты.

Результат - число шагов по 0,125 °C. Для 25 градусов это 200.

Тип `i16` выбран намеренно. Сдвиг знакового числа сохраняет знак. Если заменить `i16` на `u16`, отрицательные температуры превратятся в большие положительные, и именно этот случай мы проверим в [главе 6](06-testing.md).

Метод назван `raw`, хотя содержит уже сдвинутое значение. Имя отражает то, что число ещё не переведено в градусы.

Следом идёт метод, который возвращает градусы.

```rust
pub fn read_temperature(&mut self) -> Result<f32, Error<I2C::Error>> {
    let raw = self.read_temperature_raw()?;
    Ok(f32::from(raw) * DEGREES_PER_STEP)
}
```

Он ничего не знает про шину, а только вызывает предыдущий метод и умножает результат на 0,125. Деление на два метода полезно тем, что пользователь без плавающей точки (на дешёвых ядрах она медленная) может работать с целыми шагами. Например, температуру в миллиградусах можно получить как `i32::from(raw) * 125`.

## Изменение регистра конфигурации

```rust
fn modify_configuration(
    &mut self,
    change: impl FnOnce(u8) -> u8,
) -> Result<(), Error<I2C::Error>> {
    let mut current = [0u8; 1];
    self.i2c
        .write_read(self.address.bits(), &[register::CONFIGURATION], &mut current)
        .map_err(Error::I2c)?;

    let updated = change(current[0]);
    self.i2c
        .write(self.address.bits(), &[register::CONFIGURATION, updated])
        .map_err(Error::I2c)
}
```

Это шаблон "прочитать, изменить, записать". В регистре конфигурации восемь бит, и нужен только один. Если просто записать `0b0000_0001`, остальные биты (режим выхода OS, очередь ошибок) молча обнулятся. Поэтому сначала значение читается, потом меняется один бит, потом результат записывается.

Сама функция приватна (в объявлении нет `pub`), она служит внутренним помощником. Публичных методов два.

```rust
pub fn shutdown(&mut self) -> Result<(), Error<I2C::Error>> {
    self.modify_configuration(|config| config | SHUTDOWN_BIT)
}

pub fn wake(&mut self) -> Result<(), Error<I2C::Error>> {
    self.modify_configuration(|config| config & !SHUTDOWN_BIT)
}
```

Первый устанавливает бит операцией ИЛИ, второй сбрасывает операцией И с инвертированной маской ([глава 4](04-rust-minimum.md)).

Последнее выражение в `modify_configuration` не заканчивается точкой с запятой. Это возвращаемое значение функции: результат вызова `write` уходит наружу как есть.

## Как драйвер использует пользователь

Ниже схематичный пример. Создание шины зависит от платы и здесь заменено комментарием. Пример не компилировался с конкретным HAL.

```rust
use lm75_guide::{Address, Lm75};

// let i2c = ...;   // шина вашей платы, реализует embedded_hal::i2c::I2c

let mut sensor = Lm75::new(i2c, Address::default());

let celsius = sensor.read_temperature()?;
// дальше celsius можно вывести на дисплей или отправить по UART
```

Работа с настоящей платой будет описана в отдельной главе. Следующая глава показывает, как проверить драйвер до появления платы.
